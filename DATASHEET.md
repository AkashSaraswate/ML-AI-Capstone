# Datasheet: BBO Capstone Query Dataset

This datasheet documents the dataset generated during the Black Box Optimisation
capstone challenge: the eight functions' initial observations plus every weekly
query and its returned value.

## Motivation

**Why was this dataset created?**
It was created to solve the capstone challenge of maximising eight unknown black
box functions under a tight query budget. Each row records an input point and the
scalar output the challenge portal returned for it. The dataset is both the record
of the search and the evidence base the Gaussian Process surrogate learns from each
week.

**What task does it support?**
Sequential Bayesian optimisation. The accumulated observations condition the choice
of each next query, so the dataset is the memory of the optimisation process. It
also supports after the fact analysis of which strategies worked, which is the basis
of the weekly reflections.

## Composition

**What does it contain?**
For each of the eight functions, an input matrix and an output vector. Inputs are
points in the unit hypercube; outputs are the function's scalar value, framed so that
higher is always better.

**Size and format.**
Each function began with ten initial observations supplied as NumPy arrays
(initial_inputs.npy and initial_outputs.npy). One query per function was added per
weekly round across ten rounds, so each function now holds about twenty observations,
roughly 160 input vectors and 160 scalar outputs in total. Dimensionality ranges from
2D (F1, F2) through 3D, 4D, 5D and 6D to 8D (F8). Queries are also recorded as hyphen
separated six decimal strings in a running log with the returned value beside each. The
output scales differ enormously between functions, from near zero on F1 and the sub one
range on F2, F3, F4 and F6, up to roughly 3.3 on F7, around 9.9 on F8, and into the
thousands on F5.

**Are there gaps?**
Yes, and they are deliberate. Sampling is concentrated around promising regions
rather than spread evenly, so large parts of several input spaces, especially the
higher dimensional ones, are unsampled. The radiation function (F1) shows the
clearest gap: early rounds over sampled one region and left the region that actually
mattered almost untouched until the dataset was re ranked by output value.

**Confidential data?**
No. The data is fully synthetic, generated by mathematical benchmark functions, and
contains no personal or sensitive information.

## Collection process

**How were the queries generated?**
The initial ten points per function were provided by the course. Every subsequent
point was chosen by the optimisation strategy: a three kernel Gaussian Process
ensemble (Matern 2.5, Matern 1.5, RBF) scoring Latin Hypercube candidates with a
hybrid of Expected Improvement, Probability of Improvement and Upper Confidence
Bound, with bespoke handling for two functions (a known benchmark optimum for F7 and
a physics style decay model for F1). Each chosen point was submitted to the portal,
which returned the output.

**Sampling strategy.**
Space filling early, then increasingly exploitative, annealing the exploration
weight down as the budget was spent. Confirmed peaks were re queried to test whether
they were real or noisy.

**Time frame.**
Collected weekly across modules 12 to 24, one round per week, ten rounds so far.

## Preprocessing and uses

**Transformations.**
The only challenge level transform is framing every task as maximisation; naturally
minimised objectives are negated so higher is better. Within modelling, outputs are
standardised with a StandardScaler before GP fitting and inputs are kept on the native
unit cube; both are reversible and the raw values are preserved unchanged. For the
radiation function (F1), whose outputs span dozens of orders of magnitude, readings were
compared on a log scale when triangulating the source, since the raw values are
unusable directly. All reported results remain in the original output scale.

**Intended uses.**
Driving the weekly optimisation, studying exploration versus exploitation, and
documenting a reproducible search process.

**Inappropriate uses.**
It should not be treated as a representative sample of each function's global
structure, because sampling is biased toward exploited regions. It is also not real
radiation, chemical or pharmacological data; the application framings are
illustrative only.
